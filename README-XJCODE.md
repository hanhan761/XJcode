# XJCode（Windows 校园试用版）

XJCode 是基于 OpenAI Codex 源码的本地编程命令行工具，使用西安交通大学交晓智作为模型后端。上游固定在 commit `e790ce271749ce431e446a9e2cc66485fe60f931`；保留 Apache-2.0 许可证及 NOTICE。本项目不是 OpenAI 或学校的官方发行版。

## 安装与开始

普通用户：从[官方网站](https://xjcode.wenshanzhike.com/)下载并双击 **XJCode-Setup.exe**，自动准备 Node.js 和 XJCode，无需解压或管理员权限。安装完成后重新打开 PowerShell。

已有 Node.js 22 或以上：直接用 npm 安装 .tgz 文件或网站提供的 tarball URL。安装命令：

~~~powershell
npm install -g https://xjcode.wenshanzhike.com/releases/0.1.4/xjcode-0.1.4.tgz
xjcode login
cd D:\your-project
xjcode
~~~

网站安装器和 npm 包均自带原生组件；npm 包无需 postinstall 脚本和二次下载。网站提供直接安装 URL，npm 官方短包名尚未发布，详见 [安装与发布说明](INSTALLATION.md)。Windows x64 和 WebView2 Runtime 为运行要求。

`xjcode login` 打开独立校园登录窗口。完成学校认证后，程序自动读取当前账号的有效 API 密钥、核验账号归属，列出工作区及授权模型供选择。不会要求手工复制 token，也不会读取其他工具保存的凭据。已登录且密钥有效时，再次 login 直接复用；`xjcode login --force` 重新打开校园认证，可切换账号。

```powershell
xjcode login status
xjcode models
xjcode models --refresh
xjcode models --select
xjcode doctor --probe
xjcode exec "检查当前项目的测试失败原因并修复"
xjcode resume
xjcode mcp --help
xjcode logout
```

`doctor --probe` 会调用一次 `~/.xjcode/config.toml` 中当前默认模型；可用 `xjcode doctor --probe -m qwen3.7-max` 明确检查某个交晓智授权模型，不修改默认设置。普通 `doctor` 只核验身份和模型目录。读写文件、执行命令、审批与沙箱、会话恢复、AGENTS.md、skills 和本地 MCP 由 Codex 引擎提供。具体 CLI 参数见 `xjcode exec --help`。交互界面部分提示仍沿用上游英文。

## 与本机 Codex 并存

| 项目 | XJCode | 已有 Codex |
| --- | --- | --- |
| 命令 | `xjcode` | `codex` 保持原样 |
| 安装目录 | 网站安装器使用 `%LOCALAPPDATA%\XJCode`；npm 使用独立 `xjcode` 包目录 | 保留原位置 |
| 凭据、配置和会话 | `%USERPROFILE%\.xjcode` | `.codex` 保持原样 |
| 数据库 | XJCode 子进程独立指定 `.xjcode` | 不继承到 XJCode |

安装器只添加 XJCode 自己的 PATH 项，不设置全局 `CODEX_HOME`，不修改 PowerShell profile、不创建 `codex` 别名。引擎环境覆盖仅对 XJCode 子进程生效。网站安装器拒绝安装到 `.codex` 目录。`AGENTS.md` 仍是项目本身的协作规则。

## 登录和数据

- 校园密码只输入学校原始登录页面；程序不采集密码。登录组件只接受校园域名的 HTTPS 导航；学校两个已确认的历史 HTTP 跳转会自动升级为 HTTPS。
- 使用独立临时 WebView2 数据目录。登录窗口和原生 API 都直连校园服务，避免系统代理导致 `ERR_CONNECTION_CLOSED`；不修改系统代理。
- 优先复用当前账号最新的有效 API 密钥。没有有效密钥且不足两个时创建一个；已有两个但均不可用时提示用户在校园平台管理，不擅自删除或禁用任何密钥。
- API secret 解密后以 Windows DPAPI 当前用户方式加密保存于 `%USERPROFILE%\.xjcode\credentials.dpapi`。用户可通过绝对路径 `XJCODE_HOME` 改变目录。配置及会话与 `.codex` 分离。
- 登录组件通过限当前用户访问的命名管道交付凭据，不通过命令参数、日志或模型上下文传递密钥。logout 仅删除本机凭据，不撤销服务器密钥，也不删除已有会话。
- 模型请求直接调用学校原生 HMAC TOP 接口，无本地 HTTP 中转服务，无 OpenAI 模型回退。当前平台原生入口是 `http://ai.xjtu.edu.cn:30040/`；HMAC 验证请求签名，**不提供传输加密**。代码上下文和工具结果会发送到校园平台，并形成平台会话，应在受信校园网络使用。网页认证仍使用 HTTPS。

## 第一版范围

当前适配文字对话，以及交晓智目录声明支持图片、或在同一账号与模型部署下经双图实测确认的图片输入。默认保守上下文窗口为 32768 tokens；可通过引擎配置调整，但需与实际模型容量匹配。可选模型只来自当前账号的真实授权，图片能力不根据模型名称猜测。语音、OpenAI Web Search、云任务、远程 app-server 及自动更新不在本版范围。

图片使用：更新后重新打开 `xjcode`，通过 `/model` 选择说明中带“支持图片”的交晓智模型，再拖入单张图片文件，或用 `Alt+V` 粘贴截图；终端能将 `Ctrl+V` 传给应用时也可使用。输入框出现 `[Image #1]` 表示附件已加入，提交后才会发送。已确认能力的模型仅显示“支持图片”，命令列表显示 `[图片]`；只来自平台声明的能力仍单独标注。2026-10-19 全部 24 个授权模型的结果见[测试报告](docs/xjcode/vision-20261019/REPORT.md)，7 个经双图确认。平台声明支持的模型也可能暂时调用失败。程序不会自动切换模型。

实测能力单独保存在 XJCode 用户目录 `image-capabilities.json`，只对相同账号、工作区及模型部署身份生效；不增加模型授权。目录刷新会重新匹配并保留仍有效的结果，部署或账号变化时不沿用；损坏或不完整记录不启用额外图片能力。记录包含本地账号/工作区标识，不应随源码上传。平台保留同一部署标识但改变服务时仍需重新验证，单次测试不保证永久可用。

脚本方式可用 `xjcode exec -m qwen3-vl-plus -i "F:\images\example.png" -- "描述这张图片"`，用 `--` 分隔图片参数与任务文字。本机客户端每次模型请求最多携带 8 张图片（含未压缩的历史图片）、单张 8 MiB、合计 16 MiB；超限或格式异常会在请求前拒绝，不能把这些数值当作平台上限。图片通过独立附件字段发送，文字上下文只保留对应编号；不把 Base64 当作正文塞给模型，不在诊断日志中记录图片。现有会话文件仍按引擎行为保存图片输入。暂不自动读取远程图片地址，优先使用本地 PNG/JPEG 图片。

交晓智 Chat 返回文本，因此适配层将工具定义与历史转为显式 JSON 协议。只在完整响应结束并通过工具名称、参数 schema 校验后，交给 Codex 执行。格式错误最多修复两次；网络不确定或限流不会自动重发 Chat。模型格式遵循能力影响实际编程效果。本版先收完整回复再展示，不逐字显示尚未确认完成的回复。

## 从源码构建

安装 Rust MSVC toolchain 1.95.0、Git、Node.js 22 或更新版本（运行登录脚本测试）、Visual Studio 2022 C++ 工作负载和 Windows SDK。在仓库根目录执行：

```powershell
.\scripts\build-xjcode.ps1 -Profile dev
# 优化发行包（首次编译较久）
.\scripts\build-xjcode.ps1 -Profile release
```

脚本识别 Visual Studio，使用锁文件构建引擎、登录器和 Windows 沙箱辅助程序，运行交晓智针对性测试，生成 `dist\xjcode-0.1.4-windows-x64-<profile>.zip`。包内附 SHA256 校验清单，安装前核验。源码下载如需代理，请仅在本机配置 Cargo/Git；不要把代理凭据提交到仓库。

模块职责：

| 路径 | 职责 |
| --- | --- |
| xjcode-native/src/main.rs | xjcode 命令、登录编排和引擎启动 |
| xjcode-native/src/login.rs、login.js | 独立校园 WebView2、账号密钥获取 |
| xjcode-native/src/auth.rs、ipc.rs | DPAPI 凭据和受限命名管道 |
| xjcode-native/src/api.rs | HMAC 签名、账号/模型发现、SSE 完整性 |
| xjcode-native/src/images.rs、capabilities.rs | 真实图片附件、边界校验及有作用域的实测能力 |
| xjcode-native/src/protocol.rs | 模型工具协议及 schema 验证 |
| xjcode-native/src/setup.rs | 独立配置和 Codex 模型目录 |
| codex-rs/core/src/xjtu.rs | 原生 provider 到 Codex 事件的映射 |
| scripts/build-xjcode.ps1、install-xjcode.ps1 | 构建、打包、用户级安装 |

相对初始 GitHub 版本的源码改动、验证依据和上传范围见[实质性优化记录](XJCODE_OPTIMIZATION_LOG.md)。

## 故障排查

- 登录窗口无法连接：确认校园网络可达。当前窗口强制直连；依赖代理或 VPN 的校外环境需先建立学校提供的网络连接。
- 白屏或点击登录无反应：安装最新包，已修复校园认证旧式 HTTP 跳转被拦截的问题。
- 登录窗口初始化失败：检查 WebView2 Runtime 是否已安装。
- 登录后出现密钥上限：到交晓智个人设置检查自己的密钥状态，然后重新 login；程序不会替你撤销密钥。
- 401：重新 login；403：检查工作区/模型权限；429：等待后重试。
- 命令访问网页时报 `connect EACCES` / `Bad access`：这是连接权限拒绝迹象，与网页返回 HTTP 403 不同；先检查会话的联网权限和主机网络设置，不反复更换下载工具或猜接口。客户端会识别近期直接网络命令的此类输出，即使脚本退出 0 也不能据此宣布完成；该识别是有界规则，不涵盖任意脚本或日志格式。允许联网时可显式启动 `xjcode -s workspace-write -c sandbox_workspace_write.network_access=true -C <项目目录>`：只为该次启动开放联网，继续限制文件写入范围，不修改全局配置。已有明确受管策略仍须遵守。Windows 沙箱的 Schannel 凭据错误另按下述网页读取指引处理。
- Chat 返回 500：该次模型服务调用失败，不能据此判断登录失效。先运行 `xjcode doctor --probe` 检查短调用；短调用正常而原会话失败时，再压缩会话或手动切换授权模型。目录中有模型不代表每次请求一定成功。
- 建连失败恢复：仅当 HTTP 库明确标记连接尚未建立时，最多额外重连一次，等待 500ms，重新签名并使用原请求剩余时间；总请求预算不扩大。已发送或是否发送不确定的请求、HTTP 错误及响应体读取失败不走该重连路径。诊断区分 connect_timeout 与普通 timeout，记录连接时限和尝试次数；connect_retry_before_send 只表示再次尝试建连，不表示已重放平台操作。
- Chat 在收到响应头前发生连接失败或超时：只读回查一次原平台会话。只有两条记录中的工作区、会话、原输入消息、查询关联、输入正文及正常结束标记均匹配时，才取回对应完整回复，继续经过协议、工具参数及补丁语法校验。不会重发原 Chat，不重放已执行工具；回查失败或不能确认完整性时保留原错误。HTTP 明确拒绝、流中断、截断和过滤不由此路径恢复。诊断另记 ChatReadback 的匹配状态与字节数，不保存正文或会话标识。
- `BatchCreateMessages` 超时：这是写入上下文消息未取得确认，本次尚未发起 Chat；不能据此判断模型能力不足或上下文已满。该写入等待时间已从 20 秒调整为 60 秒，连接时限仍为 15 秒，其他普通接口 20 秒、Chat 180 秒不变。发送请求或等待响应头失败时会记录实际耗时和时限；消息可能已被平台接收，不自动重发。延长等待不能消除网络或平台故障；需要继续时先核对任务已有文件和后台作业。
- 请求失败诊断：按实际状态分别提示登录失效、权限不足、内容过大、限流或服务异常。若服务提供请求 ID / 错误码，会一同显示；模型调用还显示模型名称及输入 UTF-8 字节数（不是 token 数）。诊断保存到 XJCode 配置目录的 `diagnostics/requests.jsonl`，单文件上限约 4 MB，保留一份轮转记录；不保存请求正文、响应消息或凭据，也不自动重发失败请求。
- 回复流诊断：HTTP 成功后的流读取错误也会记录，区分超时、连接中断、UTF-8 / SSE 格式、大小限制、异常事件和缺少完成确认，并附收到的字节数、事件数、回复字节数和耗时。不会记录模型回复正文或把未确认的回复当作可执行工具；此项改善错误定位，不代表网络或平台中断已经消除。
- 普通接口响应诊断：创建会话、写入消息等非流式 JSON 接口的响应体也会区分读取超时、中断、空体、大小限制、无效 JSON 和缺少 Result，并保留接口动作、已收到的 HTTP 状态、安全请求 ID、接收字节数及读取耗时。HTTP 200 不代表响应体完整；不记录部分正文，也不自动重发结果不明的请求。
- 回复协议纠错：已完整收到但无法解析的回复按 JSON 语法、未闭合及协议字段类型分别提示，不再统一归为字符串转义。纯 JSON 语法错误使用短请求修复同一条回复，避免完整任务历史干扰；字段、参数或执行结果校验仍使用原任务上下文。最多两次纠错，修复后仍须通过原工具名称、参数 schema、补丁语法及结果校验。诊断只保留模型、次数、字节数、类别和行列，不保存回复正文；网络结果不明时不会进入格式纠错。失败时明确该轮工具未执行，已有后台任务应先检查而非重复启动。
- 长回复未闭合：回复达到 8 KiB 且 JSON 在末尾尚未完成时，转入小步骤恢复，依据原任务和已完成历史重新生成一个较小的完整步骤。要求一次只返回一个小调用、完整回复尽量在 4 KiB 内；较长脚本分轮创建或更新，原未完成批次完全不执行。摘要过长时改为精简摘要，不生成执行计划。8 KiB 是恢复分支的客户端判断值，不是有效回复大小限制或模型输出上限；4 KiB 是生成引导，不承诺模型始终遵守。短格式错误仍用原纠错方式，网络结果不明仍不自动重发。
- 自动压缩与工具调用：原生适配读取引擎明确的压缩请求标记，使用专门的交接摘要协议，只允许 final 文本。历史命令和工具声明作为摘要材料保留，不开放执行；摘要纠错也只要求生成摘要。摘要应记录失败和未完成状态，不按原任务的成功交付规则或最终报告 schema 拒绝它。下一轮普通任务恢复正常工具目录；不会根据用户文字或空的增量工具字段猜测当前处于压缩阶段。出现“本轮未开放工具”应先确认请求阶段，不应通过取消工具白名单来放行。
- Python 后台进度：Windows 启动器为新启动的 XJCode 子进程设置 `PYTHONUNBUFFERED=1`，减少普通 Python 的 print 长时间留在缓冲区。已运行进程不会被修改；显式隔离模式 `python -I` 会忽略 Python 环境变量，需要时自行使用 `-u` 或 flush。外部训练与模型请求是不同进程，模型请求失败不等于训练退出；应读取已有后台会话的输出和退出码，检查已有权重与结果，避免重复训练。
- 工具输出长度保护：发送给模型的单条工具文本超过 8 KB 时，只提供首尾预览并明确标注省略，避免压缩脚本等长输出反复占满上下文。不会修改源文件、原始会话历史、用户指令或工具调用参数；错误状态仍按原始结果判断。需要中间内容时，应通过工具按关键词或位置重新读取有限片段。
- 累计上下文保护：整份请求超过 96 KiB 时，先把较早、已完成的纯文本工具交换和过程说明折叠为有限历史预览。完整用户/系统指令、近期工具批次、未匹配调用和非文本数据保留；实际执行参数及原始记录不改写。折叠后仍超限时在发送前停止，格式纠错和直接模型调用也受同一保护。96 KiB 是客户端传输预算，不是平台模型的真实 token 上限。交晓智未返回 token 用量时，复用引擎本地估算驱动自动压缩，不伪造平台用量或计费数据；自动压缩会生成交接摘要并更新活动上下文，旧会话记录保留。
- Windows Python：启动时优先使用已有真实解释器；仅命中 WindowsApps 占位程序时，通过 Python Launcher 查询 Python 3 的实际路径，并仅调整 XJCode 子进程的 PATH。不会更改系统 PATH。普通 Python 与 Abaqus 等软件的专用解释器需分别使用；失败时先检查解释器与错误输出。未实际求解的任务不能用随机数据或编写成功日志代替真实结果，协议已补充相应证据要求，但这属于行为引导。
- Windows 执行证据：环境检查和文档读取分开调用，原生程序失败时立即保留退出码；没有实际输出时不能声称路径、版本或测试字符串已验证。简单命令直接使用当前 PowerShell，复杂代码写入脚本，避免多层 `cmd /c` 引号；读取 UTF-8 文件使用 `Get-Content -LiteralPath <路径> -Encoding UTF8`。这些提示用于减少模型误报，不构成对任意命令或自然语言结论的完整校验。更新后须重新启动程序，旧窗口继续运行其原有版本。
- PowerShell 命令入口：本地修复版统一通过 `%LOCALAPPDATA%\XJCode\commands\xjcode.cmd` 启动。若终端继承了安装前的 PATH，可运行 `scripts/repair-xjcode-command.ps1`，在既有用户 npm 命令目录增加仅针对 XJCode 的转接文件，当前旧 PATH 也能找到最新入口；不修改 PowerShell 配置文件或 npm 设置。以后直接输入 `XJcode` 即可，已运行的会话需先退出再启动。
- Windows 与任务网页：PowerShell 中需要 curl 参数时使用 `curl.exe`，读取 UTF-8 文件应显式指定编码。若 Windows 沙箱内出现 Schannel / `SEC_E_NO_CREDENTIALS (0x8009030e)`，可检查本机 Node.js 并用内置 `https` / `fetch` 下载，保留证书校验。动态网页可能只有加载入口，应从页面代码或文档定位实际数据来源，避免反复把整份压缩 JS 放进上下文或盲猜接口。工具协议已补充上述引导，模型仍可能需要纠正。首次验证可以直接提供任务正文，分别检查题目读取、环境准备和任务求解。
- 中文网页下载：Node.js 的 HTTP 响应应使用 `res.setEncoding('utf8')`，或先收集 Buffer 再统一解码。逐块把 Buffer 累加到字符串可能损坏跨块的中文字符；下载后应检查 JSON 完整性及替换字符，损坏时重新获取原文。
- 回复被截断或工具格式连续不合法：不会执行该轮工具；检查诊断，先核对已有后台任务和产物，再续接会话。格式纠错不能保证所有模型都能恢复；必要时压缩上下文或手动切换其他授权模型。
- 模型目录变化：运行 `xjcode models --refresh`；默认模型已下线时运行 `xjcode login` 重新选择。
- XJCode 的项目配置使用 `.xjcode/config.toml`。从用户主目录启动时，不再将已有的 `.codex/config.toml` 作为项目配置覆盖交晓智模型设置。
- 模型范围：模型列表只使用从交晓智同步的授权目录；启动、切换、审查及子任务选择均校验目录中的准确名称。自定义目录不能替换此列表，缺失目录时停止，不回退到其他平台的内置模型或缓存。恢复旧会话沿用当前授权模型，禁用其他后端的自动模型回退。默认模型保留用户当前选择，可以手动切换到目录中的其他交晓智模型。
